request lifecycle

One TCP connection may serve multiple HTTP requests when the client keeps the connection open.

steps

  • 1 — main thread accept() on listening socket
  • 2 — malloc _client, enqueue handler on thread pool
  • 3 — worker read() up to 8191 bytes into heap buffer
  • 4 — parser splits line, headers; body not stored today
  • 5 — lookup URI in routes dict; else static_dir + uri
  • 6 — handler returns full response string; write() to socket
  • 7 — repeat if Connection is not close; then close(fd)

All per-request memory is freed in the worker before the next read or before close.
