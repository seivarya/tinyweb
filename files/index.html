minimalist web server

a compact http server written in c, focused on clarity over abstraction. it handles raw requests, constructs responses, and serves content directly without relying on heavy frameworks.

core behavior

the server listens on a socket, accepts incoming tcp connections, and parses incoming http requests line by line. based on the requested path, it resolves files from disk or routes execution logic for dynamic responses.

request lifecycle

a typical request begins with a GET call. headers are parsed, the resource is located, and a valid http response is constructed with correct metadata such as content-type and content-length. the response is then streamed back to the client.

why this approach

stripping away abstraction exposes how the web actually works — sockets, byte streams, and protocol structure. this makes debugging easier and gives full control over performance and behavior.

possible extensions

support for POST, routing layers, thread pools, mime-type expansion, logging, and basic caching can be added without changing the core structure.
